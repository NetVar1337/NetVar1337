# Decepticon GitHub Profile README Design

## Purpose

Present NetVar1337 as an owner of [Decepticon.red](https://decepticon.red/), a governed AI red-team control plane, while retaining a compact path to relevant security research and contact details.

## Audience and outcome

Visitors should immediately understand the Decepticon role, its operator-controlled model, and where to find the product, open-source project, Ghidra MCP work, and Discord contact.

## Content structure

1. A centered Decepticon logo sourced directly from `PurpleAILAB/decepticon-landing/public/logo.png` via GitHub’s immutable raw URL for the pinned commit `7e06cea`.
2. A compact header identifying **NetVar** as an owner of Decepticon.red and Discord username `netvar`.
3. One positioning sentence: governed AI red-team control plane with runtime operator control.
4. Three product claims, limited to claims stated on the official site:
   - Scope and Rules of Engagement enforced at runtime.
   - OPPLAN tracks objectives, blockers, pivots, evidence, and next actions.
   - Specialist agents use ATT&CK and Skillogy context.
5. A concise link row to Decepticon.red, the public Decepticon project, and the profile’s Ghidra MCP project, followed by the plain-text Discord username.

## Deliberate exclusions

- Do not embed videos or animated assets: GitHub profile READMEs do not reliably play them.
- Do not add dynamic statistics, visitor counters, badges, or third-party image services: they add dependencies and stale claims without improving the profile’s primary message.
- Do not duplicate the landing page’s benchmark figures or pricing/beta dates: those time-sensitive details belong on the official site.

## Rendering and verification

The completed README must render with a visible image, accessible alt text, valid HTTPS links, and readable plain text if images fail. Validate that the raw GitHub asset URL resolves and that all Markdown link destinations match the intended public URLs.
